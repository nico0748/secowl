# 進め方 — {{title}}

> この診断対象をどの順で進めるかの手順書です。詳しい技法はアプリの「進め方」と「ツール」に載せています。
> フロー: E0 事前準備 → E1 偵察 → E2 脆弱性調査 → E3 検証・トリアージ → E4 報告

## フェーズと完了条件

| | フェーズ | 完了条件 |
|---|---|---|
| E0 | 事前準備 | スコープと RoE に書面の承認がある。1 つでも欠けたら着手しない |
| E1 | 偵察・列挙 | 攻撃面（画面・API・認証境界）の一覧がそろい、入力点を棚卸しした |
| E2 | 脆弱性調査 | チェックリストの全項目が「検出有」か「検出無」になった |
| E3 | 検証・トリアージ | 全発見事項に再現手順・証跡・CVSS・修正案がそろった |
| E4 | 報告 | 経営層と技術者の二層に書き分けた報告書を納品した |

## E0 事前準備

- [ ] スコープと RoE に承認をもらった（`00-診断対象/スコープとRoE.md`）
- [ ] 対象外と禁止行為を書き出した
- [ ] 診断元 IP と緊急連絡先を控えた
- [ ] 自分を特定できる User-Agent を決めた
- [ ] 検証用プロキシのスコープを対象 FQDN だけに絞った

## E1 偵察・列挙

着手順は次のとおりです。受動から能動へ進みます。

- [ ] 受動的偵察（WHOIS・CT ログ・検索エンジン・Shodan / Censys）
- [ ] サブドメイン列挙（subfinder / amass）とスコープ照合
- [ ] 生存確認と技術検出（dnsx / httpx / Wappalyzer）
- [ ] ポートとサービスの特定（nmap）
- [ ] catch-all の判定（存在しないパスの応答サイズをトップと比べる）
- [ ] パス・画面の列挙（sitemap と HTML のリンクを先に、そのあと ffuf）
- [ ] セキュリティヘッダと TLS の確認
- [ ] 入力点の棚卸し（フォーム・パラメータ・Cookie・ヘッダ・JSON）
- [ ] 認証境界の整理（未認証 / 一般 / 管理）

成果物は `10-偵察/` のサーフェスと `10-偵察/攻撃面マップ.md` です。

## E2 脆弱性調査

境界を固める順に進めます。

1. A02 設定ミス
2. A04 暗号化の失敗
3. A03 サプライチェーン
4. A01 アクセス制御
5. A05 インジェクション
6. A06 設計・ビジネスロジック
7. A10 例外処理
8. A08 整合性 / A09 ログ・監視
9. 横断（CSRF / オープンリダイレクト / クリックジャッキング / アップロード）

検証は無害な手段に徹します。一意マーカー `POC-{{engagement}}-NN` を使い、投入物は必ず削除します。
検出しなかった項目は `20-調査/未検出記録.md` に根拠を書きます。

## E3 検証・トリアージ

- [ ] ツールの検出をすべて手動で再現した
- [ ] 再現しなかったものを未検出記録の試行ログへ回した
- [ ] CVSS v3.1 のベクタと算定根拠を書いた
- [ ] 同種の発見事項で基準をそろえた
- [ ] 短期の回避策と恒久対策を分けて書いた
- [ ] 証跡の実トークンと個人情報をマスキングした

優先順位は、深刻度・到達性・影響資産・修正コストの 4 つで決めます。

## E4 報告

- [ ] 自動生成ブロックを最新のデータで更新した
- [ ] エグゼクティブサマリを非技術者の言葉で書いた
- [ ] 検証したが検出に至らなかった観点を付録に載せた
- [ ] 制限事項と免責を書いた
- [ ] 公開前に通読してマスキングを確認した
