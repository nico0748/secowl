## 機能

ブラウザとサーバの間に入り、HTTP(S) のリクエストとレスポンスを捕まえて書き換えます。Web アプリ診断の作業時間の大半はこのツールの上で進みます。

| 機能 | 用途 |
|---|---|
| Proxy | 通信を捕まえる。Intercept を切っても History に全件残る |
| Repeater | 1 本のリクエストを手で書き換えて何度も送る。検証の中心 |
| Intruder | パラメータを総当たりする。Community 版は速度制限あり |
| Target / Site map | 到達したエンドポイントの一覧。認証前後で 2 つ取る |
| Decoder / Comparer | エンコード変換と差分比較 |
| Logger | 全通信の時系列ログ。証跡の時刻合わせに使う |

## 使いどころ

- 認可の検証: 利用者 A のトークンで利用者 B のリソース ID を要求する。Repeater でヘッダだけ差し替える
- 入力の検証: パラメータ 1 つに無害な検証文字列を入れ、応答のどこに出るかを見る
- 業務ロジック: 金額・数量・ステップ番号を書き換えて、サーバ側で再計算しているかを確かめる

## 基本の手順

1. Target → Scope に診断対象のホストだけを登録する。**これを先にやらないと対象外の通信まで記録されます**
2. Proxy → Options で「Intercept Client Requests」を必要なときだけ有効にする
3. ブラウザのプロキシを 127.0.0.1:8080 に向け、`http://burp` から CA 証明書を入れる
4. 画面を一通り操作して Site map を埋める（認証前・一般ユーザ・管理ユーザの 3 回）
5. 気になるリクエストを `Ctrl+R` で Repeater に送り、そこで検証する

## 入れておきたい拡張（BApp Store）

| 拡張 | 用途 |

| Autorize | 低権限のセッションで同じ要求を自動再送し、認可漏れを一覧にする |
| Param Miner | 隠しパラメータとヘッダを推測して見つける |

| Logger++ | 全通信を検索可能な表にする |
| Hackvertor | 入れ子のエンコードをタグで書ける |

## 注意点

- スコープ外への通信を記録すると、それ自体が情報の持ち出しになります。Scope と「Sitemap に in-scope のみ記録」を必ず設定してください
- Intruder の並列数を上げると対象に負荷がかかります。RoE で負荷試験を禁じている場合は 1 並列に落とします
- プロジェクトファイルには実トークンが残ります。診断対象終了後の保管と廃棄の方針を決めてください
