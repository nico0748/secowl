steps:
  - title: A02 設定ミスを見る
    detail: 偵察の続きとして最初に片付きます。ディレクトリリスティング、詳細エラー、.git や .env の露出、管理エンドポイントの無認証公開、過剰な CORS、不要な HTTP メソッドを確認します。
    tools: [nuclei, nikto, ffuf, secret-scanning]
  - title: A04 暗号化の失敗を見る
    detail: TLS 1.0 と 1.1 の有効性、弱い暗号スイート、証明書の期限と CN/SAN、HTTP から HTTPS へのリダイレクト、混在コンテンツを確認します。
    tools: [testssl-sh]
  - title: A03 サプライチェーンを照合する
    detail: 偵察で特定した CMS・フレームワーク・JS ライブラリのバージョンを、既知の CVE と突き合わせます。外部スクリプトの SRI 欠如もここで見ます。
    tools: [wappalyzer, nuclei, nessus-openvas]
  - title: A01 アクセス制御の境界を固める
    detail: 認証、セッション、認可の順に境界を確かめます。水平越境は ID を他人の値へ差し替え、垂直越境は低権限の UI を操作しつつリクエストだけ高権限の経路へ向けます。強制ブラウジング、メソッド改変、SSRF、パストラバーサルも同じ枠で扱います。
    tools: [burp-suite, owasp-zap, interactsh]
  - title: A05 インジェクションを入力点ごとに網羅する
    detail: 入力点の一覧を単位にして、反射型 XSS・格納型 XSS・DOM ベース XSS・SQLi・コマンド注入・SSTI を確認します。検出は一意マーカー・数式・時間差で行い、破壊的なペイロードは投げません。
    tools: [burp-suite, sqlmap, nuclei, cyberchef]
  - title: A07 認証の失敗を見る
    detail: ユーザ列挙の応答差とタイミング差、Cookie の Secure・HttpOnly・SameSite、セッションの再生成と失効、JWT の alg:none と署名検証を確認します。大量試行は行わず、挙動の確認にとどめます。
    tools: [burp-suite, jwt-tool]
  - title: A06 設計とビジネスロジックを見る
    detail: 仕様を理解してから入ります。重要操作の再認証、アンチオートメーション、ステップスキップ、レースコンディション、レート制限なしの資源消費を確認します。自動診断では漏れる領域です。
    tools: [burp-suite]
  - title: A10 例外処理の壊れ方を見る
    detail: 巨大値・負数・null・型不一致を与え、500 と内部情報の露出、404 と 500 ページでの製品情報の露出、エラー時に認可が緩むフェイルオープンを確認します。
    tools: [burp-suite]
  - title: A08 整合性と A09 ログで締める
    detail: hidden・Cookie・JWT といったクライアント値を無条件に信頼していないか、異常アクセスに対する検知と遮断があるかを確認します。
    tools: [burp-suite, wireshark]
  - title: 横断項目を確認する
    detail: CSRF、オープンリダイレクト、クリックジャッキング、ファイルアップロードの検証を確認します。該当機能がない場合は「該当なし」と記録します。
    tools: [burp-suite, owasp-zap]
  - title: 検出に至らなかった観点を根拠付きで残す
    detail: 「問題なし」とだけ書いた記録は使えません。何を・どのように確認し、なぜ問題なしと判断したかを書きます。この記録が報告書の付録になります。

  - 検出しなかった項目に根拠を書いた

## 進める順序

境界を固める順に進めると、効率が良く漏れも出にくくなります。

```
1. A02 設定ミス       偵察の続き。すぐ終わる
2. A04 暗号化         同上
3. A03 サプライチェーン バージョンが分かっていれば CVE と照合
4. A01 アクセス制御    認証・セッション・認可の境界を固める
5. A05 インジェクション 入力点ごとに網羅
6. A06 設計・ロジック   仕様理解が前提
7. A10 例外処理       壊れ方を見る
8. A08 整合性 / A09 ログ 締め
9. 横断（CSRF / オープンリダイレクト / クリックジャッキング / アップロード）
```

## 基本姿勢

| 原則 | 具体的には |
|---|---|
| 手動を中心に置く | 認可・ロジック・レースは自動診断で漏れます |
| 無害に検証する | 一意マーカー・数式・時間差で確認します |
| 認証前後で差分を取る | 同じ経路の未認証・一般・管理の応答差から隠れた機能が見えます |
| 網羅性を担保する | 全項目を「検証済み」にします |
| 越境はトークン差し替えで試す | UI は低権限で操作し、リクエストだけ高権限の ID へ向けます |

## 無害な検証の型

| 対象 | 無害な確認 |
|---|---|
| 反射型 XSS | 一意マーカーを送り、出力コンテキストでの扱われ方だけを見る。スクリプトは実行させない |
| SQLi | エラーの有無、真偽式による応答サイズの差、時間遅延の 3 段で見る。データは取得しない |
| コマンド注入 | 時間遅延だけで判定する。外部へ接続させない |
| SSTI | `{{7*7}}` が 49 になるかだけを見る |
| SSRF | 自分が管理する受信サーバへの到達の有無だけを見る。内部資源は取得しない |

## 一意マーカー

投入する値には必ず一意の文字列を混ぜます。

```
POC-<対象番号>-<試行番号>     例: POC-10-03
```

自分の投入物を検索で見つけられるため削除漏れを防げます。反映先も一目で分かります。運用側のログで診断だと識別できます。

## OWASP Top 10:2025 の対応

| | カテゴリ | 要点 |
|---|---|---|
| A01 | アクセス制御の不備 | IDOR・権限昇格・SSRF を含む |
| A02 | 設定ミス | 既定値・過剰公開・不要機能 |
| A03 | サプライチェーンの失敗 | 依存・CI/CD・配布経路 |
| A04 | 暗号化の失敗 | TLS・保存・実装 |
| A05 | インジェクション | SQLi・XSS・コマンド・SSTI・XXE |
| A06 | 安全でない設計 | 設計段階の欠陥・ロジック |
| A07 | 認証の失敗 | 資格情報・セッション・JWT |
| A08 | 整合性の不具合 | デシリアライズ・更新検証 |
| A09 | ログ・監視の失敗 | 検知と記録の不足 |
| A10 | 例外処理の不備 | エラー・境界・フェイルオープン |

## 検出なしの根拠の書き方

良くない書き方は「問題なし」です。根拠がないため、第三者が妥当性を判断できません。

良い書き方は次のとおりです。

> `?id=` を 1000 から 1010 まで変更して送信した。すべて 403 を返し、応答本文と応答時間にも差がなかった。

この粒度で残すと、そのまま報告書の付録になります。
